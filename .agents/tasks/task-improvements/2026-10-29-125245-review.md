<details>
<summary>Details</summary>

### Package pinning regression

`package.json` shows caret ranges for all four new packages added in FEAT-001. The `^` means a future `npm install` can silently pull in patch or minor upgrades. `package-lock.json` resolves to the intended versions today, but this contradicts the stated policy.

### Admin API role gap

`/api/admin/import` and `/api/admin/log` call `supabase.auth.getSession()` and return 401 if there is no session, but do not query `profiles` to confirm the role is `admin`. This means any user who has completed Supabase auth (e.g., a future student account from item 20, or any confirmed email) could import bulk papers or write to the activity log. The middleware at `/admin/:path*` enforces role for page navigation — it does not cover direct API calls from outside the admin UI.

### Not tested

No new unit tests cover any of the 23 features. The 30 pre-existing tests pass. The new API routes (`/api/request`, `/api/papers/[id]/rate`, `/api/admin/import`, `/api/admin/log`, `/api/cron/publish`), the rating/bookmark/download-history storage logic, and the CSV parser in the import page are all untested. Not flagged as a blocker given the project's test scope, but worth noting for the cron endpoint in particular — a bug in the `publish_at` query filter could silently fail to publish or over-publish papers.
