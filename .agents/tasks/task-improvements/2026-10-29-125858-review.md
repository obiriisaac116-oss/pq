### Prior findings resolved

**Package pinning** — `package.json` now shows bare version strings (`"recharts": "2.12.7"`) for all four packages. The caret ranges from the original FEAT-001 commit are gone.

**Admin API role enforcement** — All three routes (`/api/admin/import`, `/api/admin/log`, `/api/admin/unread-count`) now follow the same pattern: `getUser()` for session, then a `profiles` lookup via admin client to confirm `role = 'admin'`, returning 401 on no session and 403 on wrong role. The import route additionally validates that `rows` is a non-empty array before attempting any DB access.

### Cron endpoint security

`/api/cron/publish` returns 401 when `CRON_SECRET` is unset or the header doesn't match. The guard is a direct string comparison — no timing-safe compare — but for a cron secret of this kind this is an acceptable trade-off and consistent with the ecosystem pattern.

### Not tested

No new unit tests cover any of the 23 features. The 30 pre-existing tests pass. New API routes (`/api/request`, `/api/papers/[id]/rate`, `/api/admin/import`, `/api/admin/log`, `/api/cron/publish`), the rating/bookmark/download-history storage logic, and the CSV parser in the import page are all untested. Not a blocker at this project's scope, but the cron publish query filter is worth a manual smoke test before enabling the Render cron job in production.
